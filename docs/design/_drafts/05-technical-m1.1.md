## A2. Model v3 (fixed contracts)

**Fighter** (`core/model/fighter.ts`, `progression.ts`):
- `train100: Record<StatId, number>` (13 stats), the trained value. **Interim rule until WP-B:** effective stats still read the M1 clocks (`dev100`); `train100` equals `cap100 × M_g(D_g + bloom)` at generation and migration, and the M1 season-end step refreshes it. WP-B switches `effectiveStats` to `train100` and freezes the clocks in one change (no fixture stat moves: testkit fighters carry exact values, checked by `fighters/levels.test.ts`).
- `level`, `xpIntoLevel`, `xpNeeded`, `pendingLevelUps: PendingLevelUp[]` (≤ 3), `levelUpMode: 'inherit' | LevelUpMode`, `abilityRanks: { a1, a2, passive }` (1–3), `perkIds: PerkId[]` (≤ 4), `freshness10` (0–1,000).
- `LevelOption = stat { stat, gain100 } | rank { slot, abilityId, toRank } | perk { perkId }`; `PendingLevelUp = { level, season, weekIndex, options, traitOffer: TraitId[2] | null }`.
- `SeasonCounters` += `roundXp`, `benchXp`, `levelLog: ResolvedLevelUp[]`, `tiredRoundStarts`, `spentRoundStarts`, `restWeeks`, `squadReserveMatches`. `xp` stays "all XP this season". Pick counts derive from `levelLog` (no separate counters).
- `CareerStats.levelsGained`; history rows += `levelStart`, `levelEnd`, `stamina`, `benchXp`, `tiredRoundStarts` (null on rows written before v3); trait `source` += `'level'`.
- Hand-built fighters use `blankProgression(train100)` (level 1, `xpNeeded` 155 placeholder); generated ones `initProgression`.

**Club:** `levelUpDefault` (player `manual`, AI `auto`), `levelUpPacing` (`detailed`), `autoSwap: AutoSwapRules` { mode, freshnessBelow, reserveMargin, maxRatingGap, keepOneForInjury, sameRoleFamilyFirst, lostRoundBonus }, `pauseBetweenRounds` (`always`). Defaults come from content via `clubMatchDefaults(content, who)` (`core/content/match-defaults.ts`); `club.choose` applies the player defaults. **Lineup** += `reserves: FighterId[]` (0–2; the squad is the lineup's 5 starters plus these).

**Match records** (`core/model/match.ts`):
- `FightFighterInput` += optional `freshness`, `abilityRanks`, `perkIds`, `enteredThisRound` (absent = M1 default, so every M1 input is a valid M1.1 input). `RoundInput = { round, home: SideInput, away: SideInput }` (5 active fighters per side). `RoundAftermath` and `RoundOutcome` carry what the lifecycle hooks need.
- `MatchResult` += optional `squads`, `reserveInputs`, `roundLineups: RoundLineups[]`, `betweenRounds: BetweenRoundRecord[]`, `emergencyEntrants`. Absent = an M1 result (whole-match sim). **Decision:** instead of combat's `rounds[].input` (a full RoundInput per round, about 5 KB each) a result stores the lock-time inputs once (`input` holds the round-1 five, `reserveInputs` the others) plus a small `RoundSideLineup` per side and round (ids by slot, rows, captain and vice index, the acting captain's CQ, Freshness, entered flags). `roundInputOf(result, round)` rebuilds the exact RoundInput (sw-008); replays never run a policy.
- `MatchSquad`, `SwapDecision`, `SwapRecord` (reason player / auto / injury / emergency, `costsSwap`), `SwapRejection` (the six reasons, checked in combat's order), `MatchSideState`, `MatchState` (phase `round_pending` / `between_rounds` / `done`, `inputsById`, accumulated `fighterStats`, `playerDecisions`).
- `GameState.liveMatch: MatchState | null`: the player's match while week processing waits at a between-round step.

**Commands** (validated identically for AI and player): `squad.set` (5 starters + 0–2 fit, distinct roster reserves; `lineup.set` keeps reserves who are not starting), `levelup.choose` (refused while a match is live; resolution delegated to `fighters.resolveLevelUp`), `levelup.policy` (fighter, or club default with fighterId null; the default cannot be `inherit`), `match.swap` (the player's decisions for the pending step, legality-checked; `[]` = no swaps; no command = accept the suggestions), `autoswap.set`, `pacing.set`. The four settings and picks are allowed during the season-end phase.

**Engine entry points** (`core/game/live.ts`): `advance(state)` is Continue: without a live match it is `advanceWeek`; with one it plays on (stub). `betweenRoundView(state)`, `levelUpView(state, fighterId)` (stub). The UI engine seam (`ui/store/engine.ts`) has them as optional members.

**Dependencies:** `core/save` may now import `core/fighters` (the migration derives Stamina and levels with lifecycle code); `tests/architecture/rules.ts` and §3.1 updated. New RNG stream `STREAM.migration`.

## A3. Save migration v2 → v3 (implemented)

`migrateV2ToV3(state, content)` (migrations now receive the loaded content): for every fighter, in id order, first Stamina (cap from P × 20, the class offset, the race tendency, +2.5 and a ±3 jitter; bloom −2…2; wear = his `str` wear; draws from `Rng(root, 'migration', 'm1.1', fighterId, 'stamina' | 'stamina-bloom')`), `train100` = the M1 developed value, and the peak-rating shift; then the level from the formula, `xpNeeded` with the current mentoring, `xpIntoLevel = min(season XP, xpNeeded − 1)`, no pending level-ups, Freshness 100, rank 1, no perks, zeroed counters, null history columns. Clubs get reserves `[]` and their match-day defaults; alumni careers get `levelsGained` 0; `liveMatch` null.

- **Old rating for the peak shift:** the v2 weights are not in the build, so the "before" rating is the 12-stat rating with the M1.1 weights renormalised without Stamina (the M1.1 weights are the v2 ones × 0.98, rounded). On the R001 saves the shift is −1…+1.
- **Result on the real saves** (`tests/save/r001-migration.test.ts`, fixtures `tests/fixtures/saves/*.json.gz`): T001 (season 1 week 1, before the club choice), T004 (week 17) and T004 played on with the M1 code to season 2 week 3 all load, validate against v3, keep every shown stat except Stamina, migrate byte-identically twice, advance a week and save/load again as v3. 664–700 fighters; level median 46 (4–100); Stamina median 12 (p10 8, p90 17); parse plus migration 100–175 ms.
- **Expect level-ups right after loading a mid-season save:** at week 17, 325 of 664 fighters carry XP and many sit at `xpNeeded − 1` (prog-q9: no level pops on load; the next match end triggers them, at most 2 per match, queue 3).

## A4. Decisions taken in this phase

| Topic | Decision |
| --- | --- |
| Lost-round bonus (+10, lifecycle's proposal, prog-q8) | **Adopted.** It fits combat's threshold step as an additive term: the side that lost the round just played swaps active fighters below `freshnessBelow + lostRoundBonus`; forced replacements, the reserve margin, the rating gap and keepOneForInjury are unchanged. It is a field of `AutoSwapRules` (default `levels.json aiSubstitution.lostRoundThresholdBonus` = 10) for every club, AI and player alike (P-04); on the player's screen it only changes the suggestions, and the player can set it to 0. | Record format | `roundLineups` + `reserveInputs` instead of a full `rounds[].input` (§A2); exactness is tested by `roundInputOf`. |

## A5. Cross-file validation added (`core/content/validate.ts` `validateM11`)

- **combat.json:** auto-swap modes and pause options equal the closed lists; reservesMin ≤ reservesMax; `fullPenaltyAtOrBelow` < `thresholdBelow`; resist clamp ordered; the default carries no penalty.
- **classes.json:** 13 weights summing to 1, Stamina 0.02, `statEmphasis.stamina` within 0.5–2.0.
- **ability-ranks.json:** one row per ability (none unknown, none duplicated); class and slot match; rankable exactly for non-basic abilities, with rank 2 then rank 3; applying the changes in order, every `from` equals the value at that rank and every `to` converts exactly; after each rank, hard-control durations unchanged, status magnitudes within caps, active cooldown ≥ 1 s and focus ≥ 10.
- **perks.json:** tags equal the closed list; unique ids and names; tier gates (minPerksHeld, tier III lists a lower-tier prerequisite of the same archetype or general); symmetric exclusions; tags from the file's list; trait effects sim-owned only; no hard control; status caps; `aiPreferences.tagWeights` keys are archetypes; maxTier3 ≤ perkCap.
- **levels.json:** ascending step tables; min ≤ max; modes and labels equal the closed lists, labels descending to 0; `freshness.threshold` = combat `thresholdBelow`, `freshness.start` = combat `default`; `matchSquad` and `aiSubstitution` equal combat's `match` values (combat owns them); personality keys = economy.json personalities; trait offers: known, not duplicated, never physique or acquired, positives boon or edge, burdens burden; `maxRolledAndLearned` equals traits.json.
